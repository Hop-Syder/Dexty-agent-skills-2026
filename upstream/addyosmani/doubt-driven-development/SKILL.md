# Doubt-Driven Development

## Overview
Apply deliberate skepticism to project requirements. Identify ambiguous phrasing, hidden race conditions, edge case blind spots, and conflicting constraints.

## Workflow
1. Review requirements with a critical lens.
2. Highlight missing failure handling, network latency issues, and boundary values.
3. Resolve doubts with the team before starting planning.
